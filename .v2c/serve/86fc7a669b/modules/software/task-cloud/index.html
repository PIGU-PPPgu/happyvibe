T2 · WorkBuddy 实操

实操 · 30 分钟让数据上云（手机电脑同步）

傻瓜级逐步教程：注册 Supabase → 建数据库 → 复制两串钥匙 → 让 AI 改好工作台 → 手机电脑看到同一份数据。每一步精确到按钮。

任务二续篇 · 上云实操

一句话结论：注册一个免费数据库，复制两串”钥匙”交给 AI，它把你的工作台改成连数据库版——从此手机电脑同步，清缓存也不怕。

开始前（30 秒自查）

  • ✅ 工作台已经上线成网址（没有？先做上一课，两课连着做）；
  • ✅ 有邮箱；准备一个密码记事本——这课要记 3 样东西。

第 1 步 · 注册 Supabase（3 分钟）

  1. 浏览器打开：supabase.com；
  2. 点右上角 「Start your project（开始项目）」；
  3. 用 GitHub 或邮箱注册——推荐邮箱（和 Cloudflare 一样的流程：填邮箱→设密码→收验证邮件→点确认）；
  4. 回到 supabase.com 登录。

✓ 成功标志：进入一个空空的仪表盘（Dashboard）。

卡住了：GitHub 注册跳转后卡住 → 回来改用邮箱注册。

第 2 步 · 创建项目（3 分钟 + 等待 2 分钟）

  1. 点 「New project（新建项目）；
  2. 按提示填三样：
    • Name 项目名：workbench（随你）；
    • Database Password 数据库密码：自己设一个并立刻记到密码记事本（丢了很麻烦）；
    • Region 区域：选 Singapore（新加坡）——离我们最近，速度快；
  3. 点 「Create new project」；
  4. 等进度条跑完（约 2 分钟，去倒杯水）。

✓ 成功标志：进入项目页面，左侧出现一排菜单（Table Editor、SQL Editor……）。

第 3 步 · 建数据表（3 分钟，复制粘贴就行）

不用懂”表”是什么——AI 已经替你想好了，你只管粘贴：

  1. 回到你搭工作台的 AI 对话（WorkBuddy 等）；
  2. 发这句：
我要把工作台数据存到 Supabase。
第一步：请根据工作台现有的数据结构（待办/学生/作业/备忘），
给我建表的 SQL 语句，我复制到 Supabase 的 SQL Editor 里运行。
  1. AI 会给你一段 CREATE TABLE ... 的代码——全部复制；
  2. 回 Supabase：左侧点 「SQL Editor」 → 点 「New query」 → 把代码粘贴进输入框 → 点右下角 「Run（运行）」；
  3. 显示 Success. ... 就成了。

✓ 成功标志：左侧点「Table Editor」，能看到几张建好的表。

第 4 步 · 复制两串钥匙（2 分钟，最关键）

  1. Supabase 左侧最底下：项目设置（齿轮图标 Project Settings） → 点 「API」；
  2. 页面上有两样东西，各复制一份（点旁边的复制图标）：
    • Project URL（网址形的一串）；
    • anon public 那一长串 Key（注意是 anon 开头那行，不是 service_role！）；
  3. 暂时存到密码记事本。

🔒 安全提醒：这两串相当于”只读访客证”，可以交给 AI 使用；service_role 那串是管理员钥匙，谁都不给、不发群。

第 5 步 · 让 AI 改造工作台（5 分钟）

回到 AI 对话，把钥匙交出去：

第二步：这是我的 Supabase 信息——
Project URL：____（粘贴）
anon Key：____（粘贴）
请把工作台代码改成读写 Supabase：
1. 所有数据（待办/学生/作业/备忘）存取都走数据库
2. 保留"导出 JSON"按钮
3. 改完把新的工作台文件夹给我

AI 会重写代码并交付新的文件夹。

✓ 验收：打开新工作台 → 加一条待办 → 换个设备（手机）打开 → 那条待办在。

第 6 步 · 重新上传上线（2 分钟）

新文件夹要替换线上版（就是上线课第 5 步）：

  1. Cloudflare → 你的项目 → Create new deployment；
  2. 把新文件夹拖进去；
  3. 等部署完成 → 手机电脑分别打开网址，各加一条待办互查——同步了。

三个必须知道

1. 数据真的在云上吗？ 在。Supabase 的 Table Editor 里点开表，能看到你每一条待办——数据可视、可导出（导出按钮随时下载全部）。

2. 免费档够用吗？ 对个人+一个班：远远够用（50MB 数据库、5 万行读/月起步）。真超了再考虑付费，那时你早已是熟手。

3. 安全红线

  • 云端版建议继续用化名（或”学号+姓名首字母”）；
  • anon Key 泄露了可以一键重置（API 页 → Regenerate）——这是它比 service_role 安全的原因；
  • 每学期点一次导出 JSON 存档，永远留后路。

检查点

  • 手机和电脑看到了同一份数据
  • 密码记事本存了：Supabase 登录密码、数据库密码、两串钥匙的出处
  • 导出按钮测试过一次
