# 资源中心（课件 + Skill 工坊 + 工具箱）与 Skill 评价标准 · 设计

日期：2026-11-24
状态：方向已确认。用户三项决策：①资源库、工具箱、工坊三仓合一成「资源中心」；②首批少而全实测；③授权 AI 代测 WorkBuddy。

## 0. 一句话

资源中心是老师「拿来就能用」的入口，分三个板块：**课件**（上课投屏）、**Skill 工坊**（交给 AI 干活的技能）、**工具箱**（打开就能用的网页工具）。工坊的立身之本是**评价标准**：每个 Skill 都回答「我为什么用、得几分、凭什么」，分数从实测记录算出来，不靠印象。

## 1. 要解决的问题（2026-11-24 线上实拍与调研的事实）

资源库现状（`/resources/`）：

| 事实 | 后果 |
|---|---|
| 只有 2 件课件，却有学科、年级、教材、章节 4 排筛选器 | 筛选器比内容多 |
| 11×3 覆盖矩阵占 560px，几乎全是「—」 | 在展示「没有」 |
| 统计条显示「0 条精选外链」「2/11 学科已上线」 | 自曝家底 |
| 课件没有详情页，教学设计只在学科分页的折叠块里 | 老师进教室前看不到怎么用 |
| 浅色主题卡片右下角「悬停实时预览」是黑底深字 | 读不出来 |
| 移动端统计卡折行参差，矩阵横向溢出 | 只露出三列 |

Skill 生态现状：

- 供给不缺，缺的是筛选。`hezkvectory/hermes-edu-skills` 有 170 个技能，`qizhitang/xiaozhi-skills` 有 84 个，光「教案设计」就有五六家各做一份。
- 市面没有面向教师的评分。SkillHub（WorkBuddy 技能市场的公开底座）的 TRACE 评测（可信任度、可靠性、适用性、规范性、有效性）评的是技能写得规不规范，以 AI 自动检测为主；skills.sh 只按安装量排名。
- 安全风险真实存在。调研引用 HarmfulSkillBench（arXiv 2604.15415）测得 4.93% 的技能被判有害（子任务报告，未复核）。
- SkillHub 协议禁止批量抓取与再分发，抽查前 30 条教育技能 28 个无许可证。只能「只评不转」；明确开源许可的才能镜像。

## 3. Skill 评价标准

### 3.1 三个问题

| 老师的疑问 | 回答它的东西 | 在哪里 |
|---|---|---|
| 我为什么用这个 Skill？ | 一句话理由 `verdict`，加一句短板 `weakness` | 卡片、详情页 |
| 它多少分？ | 十分制总分，加档位 | 卡片、详情页 |
| 从哪些维度评？ | 五个维度、一条红线、品类检查单 | 详情页评分拆解、评价标准页 |

### 3.2 五个维度与权重

| 维度 | 键 | 权重 | 老师的疑问 |
|---|---|---|---|
| 省时 | `value` | 25% | 这活我多久干一次，用了少改多少 |
| 出活 | `quality` | 25% | 出来的东西能不能直接交 |
| 好上手 | `ease` | 20% | 我装得上、叫得动吗 |
| 懂教育 | `edu` | 15% | 它懂教材、课标和学校规矩吗 |
| 放心用 | `safety` | 15% | 学生信息和我的数据安全吗 |

每维 1 到 5 分。`总分 = round1(Σ 维度分 ÷ 5 × 权重)`，十分制保留一位小数。权重理由：省时和出活合占一半，因为这两项就是「实用」；好上手决定不懂技术的老师能不能走到价值那一步；懂教育是与通用市场的差别所在；放心用是底线。

### 3.3 分数从证据算出来

评测员记录的是事实，分数由规则算出，规则写在 `src/lib/skillScore.ts`，构建与校验共用。这样两个人评同一个技能会得到同一组分。

**记录项**

- `runs`：装上技能后，主任务在新会话里跑 3 次。每次记是否触发、耗时（秒）、修改处数、严重错误数。
- `baseline`：不装技能，同一任务、同一模型、新会话跑 1 次。记修改处数与严重错误数。
- `checklist`：该品类检查单逐条通过与否。
- `textbookCheck`：教案类、命题类必填，抽 3 个章节核对技能写出的教材版本与章节是否正确。
- 安装步数 = `install.workbuddy` 的条数；配置项 = `requires` 里的条目。

**名词口径**

- 修改处：老师必须改动才能用的一处。错别字一句算一处；缺一个必备栏目算一处；一段空话算一处。每处在评测档案里列出来。
- 严重错误：老师没发现就会交上去的错误，如公式算错、编造课标条目、数据对不上。
- 触发：不点名技能，只按老师平时说话的方式发出任务，技能被调用记为触发。

**省时**

```
gain = 1 − 平均修改处数 ÷ max(baseline 修改处数, 1)
频次档：每日或每周 = 3，每月 = 2，每学期 = 1（取主任务的频次）
baseline 修改处数 ≤ 1           → 2   （不装已经够好）
平均修改处数 ≥ baseline 修改处数 → 1
频次 3：gain ≥ 0.5 → 5，否则 4
频次 2：gain ≥ 0.5 → 4，否则 3
频次 1：→ 2
```

**出活**

```
q = 检查单全项通过率
严重错误 ≥ 2 或 q < 0.4          → 1
严重错误 = 1                      → 2
q ≥ 0.9 且平均修改处数 ≤ 2        → 5
q ≥ 0.8 且平均修改处数 ≤ 4        → 4
q ≥ 0.6                           → 3
其余                              → 2
```

**懂教育**

```
qe = 检查单中「懂教育」项的通过率；tc = 教材抽检通过率（不适用品类记 1）
带「规矩」标记的项有一条不过       → 1
qe ≥ 0.9 且 tc = 1               → 5
qe ≥ 0.75 且 tc ≥ 2/3            → 4
qe ≥ 0.5                         → 3
qe ≥ 0.3                         → 2
其余                              → 1
```

**好上手**

```
requires 含付费项                 → 1
扣分 p：安装步数 > 3 记 1；
        requires 含联网、Python、Node、平台专用工具任一记 1；
        触发 2/3 记 1，触发 1/3 记 2，触发 0/3 记 3；
        在 WorkBuddy 上功能不完整记 1
ease = 5 − p，下限 1
requires 含自备密钥               → 不高于 2
```

**放心用**（事实来自静态审查）

```
起点 5
有外联且说明书里写明               → 不高于 4
有外联但说明书没写                 → 不高于 2
需要密钥或登录授权                 → 不高于 3
把学生信息存在本地文件             → 不高于 3
读取范围超过用途所需               → 不高于 2
```

**教研调整**：`overrides` 允许终审时对任一维度改分，一次一条，必须写理由。页面上标「教研调整」。未调整的维度由校验脚本重算，必须与记录一致。

### 3.4 档位

| 总分 | 档位 | 含义 |
|---|---|---|
| 9.0 起 | 必装 | 对口就该装 |
| 8.0 到 8.9 | 好用 | 有小瑕疵 |
| 7.0 到 7.9 | 可用 | 有明确短板，看短板再定 |
| 6.0 到 6.9 | 勉强 | 没得选时再用 |
| 6.0 以下 | 不推荐 | 不进正库，进「测过不收」清单并写明原因 |

首批评测完成后校准一次锚点。若全部落在 8.0 以上或 7.0 以下，说明规则太松或太紧，修订规则并在变更记录里写明。

### 3.5 红线（碰任何一条都不收，不看总分）

1. 索取学生实名、成绩等信息并外传，或无提醒地长期保存。
2. 脚本会删用户文件、读取凭据、向没说明的地址外发数据，或代码混淆。
3. 不声明就得付费，或是第三方接口的推广壳。
4. 生成公开排名、给学生贴标签等违规输出，且没有任何边界说明。
5. 说明书里藏着与用途无关的指令。

### 3.6 品类检查单

五维用来跨品类比总分；同品类分高下靠成品检查单。每条带两个标记：属于「出活」(Q) 还是「懂教育」(E)，以及是否是「规矩」项。

**备课教案**（lesson-plan）

| 编号 | 标记 | 条目 |
|---|---|---|
| LP1 | E | 教材版本、册别、章节号与课题和老师给的一致 |
| LP2 | E | 教学目标可观测，写的是学生能做什么 |
| LP3 | E | 有重难点，且写了突破办法 |
| LP4 | E | 预设易错点，每个都写了学生为什么错、老师怎么应对 |
| LP5 | E | 环节时间加起来等于课时长度 |
| LP6 | E | 每个环节都有学生活动 |
| LP7 | E | 作业或练习有分层 |
| LP8 | E | 有当堂检测，题目对应本课目标 |
| LP9 | Q | 内容具体到这一课，换个课题不能直接套用 |
| LP10 | Q | 事实、公式、引用无误 |
| LP11 | Q | 是学校教案的常见结构，能直接誊写或打印 |
| LP12 | Q | 一课时教案 1 到 2 页，没有大段空话 |

**命题作业**（assignment）

| 编号 | 标记 | 条目 |

| AS1 | E | 不超出所给学段和教材范围 |

**学情分析**（analysis）

| 编号 | 标记 | 条目 |
|---|---|---|
| AN1 | E | 写明数据口径：人数、科目、满分、缺失值处理 |
| AN2 | E · 规矩 | 不出现学生真实姓名和公开排名 |
| AN3 | E | 结论有数字支撑，能回溯到表里的数据 |
| AN4 | E · 规矩 | 不给学生贴标签 |

**家校沟通**（home-school）

| 编号 | 标记 | 条目 |
|---|---|---|

| HS4 | E | 给家长的建议具体可做 |

### 3.7 固定测试任务

同品类的技能用同一道任务，分数才可比。任务用统一的脱敏输入。

| 编号 | 品类 | 角色 | 频次 | 任务原文 |
|---|---|---|---|---|
| LP-1 | 备课教案 | 主任务 | 每日 | 我是初一数学老师，教材是北师大版。请帮我设计七年级上册第二章 2.2 数轴第 1 课时的教案，45 分钟，班级 45 人。 |
| LP-2 | 备课教案 | 副任务 | 每日 | 请做人教版八年级下册第十九章 19.1.1 变量与函数第 1 课时的教案，45 分钟。 |
| EX-1 | 命题作业 | 主任务 | 每月 | 请出一份人教版八年级下册《一次函数》单元测试卷，满分 100 分，时间 45 分钟，附答案解析和双向细目表。 |
| HW-1 | 命题作业 | 主任务（错题辅导） | 每日 | 孩子读初一，这道题做错了：数轴上点 A 表示的数是 −3，点 B 表示的数是 2，求 A、B 两点间的距离。孩子写的是 1。请先讲清错在哪，再出 3 道变式题并给答案。 |
| AN-1 | 学情分析 | 主任务 | 每月 | 附脱敏成绩表（`public/skill-tasks/grade-sample.csv`）。这是我们班期中三科成绩，请分析班级学情，给出讲评重点。 |
| HS-1 | 家校沟通 | 主任务 | 每月 | 期中考试刚结束，请帮我给全班家长写一封信，400 字左右：说明整体情况（不排名、不点名）、给家长三条家庭配合建议、通知下周四晚上 7 点开家长会。语气亲切。 |

`grade-sample.csv` 由脚本用固定随机种子生成：45 名学生，学号 S01 到 S45，语数英三科，满分各 120、100、120，含 2 个缺考。

主任务跑 3 次。有副任务的品类（目前只有备课教案）每个技能另跑 1 次副任务，检验它不是只会一道题。baseline 每道主任务只跑 1 次，同品类的技能共用。

### 3.8 测试流程与证据标记

流程（评价标准页用 archify 画成流程图）：

1. 候选：来源限 SkillHub 教育学习分类的逐条挑选、明确开源的 GitHub 仓库、教师投稿。
2. 隔离下载：每个技能放独立空目录，只读不执行。
3. 静态审查：通读全部文件；`scripts/audit_skill.mjs` 扫描外联、删除、动态执行、凭据、提权、隐藏指令；核对许可证。
4. 转载判定：MIT、Apache-2.0 等明确开源许可的镜像，否则只评不转。
5. 装进 WorkBuddy：把技能目录放进 `~/.workbuddy/skills/`，用完移除。
6. 实测：WorkBuddy 桌面版，每次新会话，主任务 3 次，有副任务的品类加 1 次；这道主任务还没有 baseline 时另跑 1 次。
7. 定分：按 3.3 的规则算分，填检查单与修改处清单。
8. 入库：写条目、评测档案、技能包，构建，截图目检。
9. 复测：上游更新后重跑；评测超过 6 个月标「待复测」。

五条规矩：

- 没实测不出分。只做过静态审查的条目是「待测」，进候选池，不显示分数。
- 每份评分写明评测日期、技能版本、所用 Agent 与模型。
- 证据标记分开显示：「AI 代测」与「教师试用」是两回事，各自有各自的标记。
- 没截图亲眼看过的输出不算测过。
- 一次只评一个技能，不批量套模板。

### 3.9 与平台评分的分工

SkillHub 的 TRACE 评分作为「平台 AI 评分」并列展示，带原页链接。它评技能写得规不规范，不评教师价值。例：它给 `k12-smart-teacher` 的可信任度 4.8，但该技能说明里写着要把学生姓名、年级存进本地记忆文件。

## 4. 数据模型

### 4.1 `skills` 内容集合

路径 `src/content/skills/<slug>.md`，frontmatter 结构化，正文是评测档案的叙述部分（输出样例、修改处清单）。注册到 `src/content.config.ts`。

```yaml
name: xiaozhi-teach-lesson-planner      # 技能自己的 name
title: 教案设计器                         # 站内显示名
category: lesson-plan                    # 八个品类之一
does: 把一节课设计成目标、评估、活动一致的教案，含分层   # 替你做什么，一句话
summary: 适合谁、产出什么，两到三句
source:
  kind: github                           # github | skillhub | own
  author: 小智伴学
  repo: qizhitang/xiaozhi-skills
  path: teacher/general/xiaozhi-teach-lesson-planner
  url: https://github.com/...            # 上游页面
  commit: abc1234                        # 评测时的上游提交
  license: MIT
  version: 2.12.7
  platformScore: { score: 4.6, url: https://skillhub.cn/... }   # 可选
distribution: mirror                     # mirror 站内镜像 | link 只评不转
platforms: [workbuddy, claude-code, generic]
composition: resources                   # prompt 纯说明 | resources 带参考文档 | scripts 带脚本
requires: []                             # api-key | paid | network | python | node | platform-tool
install:
  workbuddy: [下载技能包, 打开 WorkBuddy 点「添加技能」, 选「上传技能」并选中压缩包]
trigger: 帮我设计一节……的教案
examples: [帮我设计一节《一次函数》新课, 这是我的旧教案，帮我重做]
cautions: [...]                          # 注意事项
customize: [...]                         # 可选：改成自己学校版本该动的两三处
relatedLessons: [growth/skill-use]
status: tested                           # tested | pending | rejected
rejectReason: ...                        # rejected 必填
score:                                   # tested 必填
  dims: { value: 4, quality: 4, ease: 5, edu: 4, safety: 5 }
  notes: { value: 一句依据, quality: ..., ease: ..., edu: ..., safety: ... }
  verdict: 一句话理由
  weakness: 短板一句话
  tested: { date: 2026-11-25, agent: WorkBuddy 桌面版 5.9.3, model: auto, by: ai, skillVersion: 2.12.7 }
  platformComplete: true
  runs:
    - { task: LP-1, triggered: true, seconds: 91, edits: 3, severe: 0, shot: /images/skill-reports/<slug>/run-1.webp }
  baseline: { task: LP-1, seconds: 70, edits: 7, severe: 1 }
  checklist:
    - { id: LP1, pass: true, note: 版本章节正确 }
  textbookCheck: { total: 3, passed: 3 }
  audit: { network: none, credentials: false, studentData: none, overRead: false }
  overrides: []                          # 可选：[{ dim, value, reason }]
```

约束（zod 与 `scripts/check_skills.mjs` 共同强制）：

- `status: tested` 必须有 `score`；`pending` 不得有 `score`；`rejected` 必须有 `rejectReason`。
- `distribution: mirror` 时 `source.license` 必须在允许清单内，且 `src/skills/<slug>/SKILL.md` 存在。
- `distribution: link` 时 `source.url` 必填。
- 枚举：`platforms` 取 workbuddy、claude-code、zcode、generic；`composition` 取 prompt、resources、scripts；`requires` 取 api-key、paid、network、python、node、platform-tool。
- `runs` 恰好 3 条主任务；品类有副任务时另加 1 条。
- 未被 `overrides` 调整的维度，重算结果必须等于 `dims` 里的值。
- 总分由构建期从 `dims` 算出，不落盘。
- 站内 authored 文本（title、does、summary、notes、verdict、weakness、cautions、install、正文）不得含 emoji。

### 4.2 标准数据文件

`src/data/skill-standard.ts` 导出：维度与权重、每档锚点文案、档位阈值、红线、八个品类（名称、图标字符、对应课程模块）、各品类检查单、固定测试任务。评价标准页、详情页、校验脚本共用这一份。

### 4.3 镜像技能包

- 源：`src/skills/<slug>/`，上游技能目录原样拷贝，不改一字。
- 产物：`scripts/build_skill_packages.mjs` 打成 `public/skills/<slug>.zip`，包根放上游仓库的 `LICENSE`（技能目录里没有时补入）和一份 `ATTRIBUTION.md`（作者、仓库、提交号、许可证、评测日期）。不发布散文件，避免技能里的 HTML 被站内搜索索引。
- 详情页不内嵌 SKILL.md 原文（上游文本常有 emoji，且对老师不如评测档案有用）；全文看上游链接。

### 4.4 资源条目新增字段

`resources` 集合加两个可选字段：

- `quickstart: string[]`：课堂使用步骤，3 到 4 条，精确到按键。写入前必须在浏览器里照着点一遍。
- `relatedLessons: string[]`：相关课程 id。

## 5. 页面规格

### 5.1 资源中心页头

组件 `ResourceHubHeader.astro`，三个板块入口页共用。内容：`// RESOURCE HUB · 课件 N · Skill N · 工具 N`，标题「资源中心」，一句话「课件上课投屏，Skill 交给 AI 干活，工具打开就能用。」，板块切换（三个标签，带计数，当前页高亮，是链接不是按钮）。Skill 数只计「已实测」。放进现有的 `TerminalWindow` 外壳，保持全站一致。

### 5.2 课件板块（`/resources/`）

- 去掉统计条与覆盖矩阵。
- 学科 pill 常驻，带计数，兼作学科页入口；年级、教材、章节三排筛选只在自产课件达到 6 件时出现。
- 学科进度条：一行紧凑的学科 chip，有课件的显示件数并可点进学科页，没有的置灰不可点；下方一句「未上线的学科按教材章节逐件制作。」不展示没有依据的排期。
- 卡片网格桌面端两列；卡片保留实拍图、学科角标、教材锚点、标题、一句话用法、标签、「进入教室」。实拍图与标题链到详情页，「进入教室」链到全屏课件。卡片不整体包进链接，避免链接嵌套。悬停实时预览保留。
- 修浅色主题角标：角标文字用固定浅色，不随主题变量变深。
- 移动端：单列，筛选器横向可滚。

### 5.3 课件详情页（`/resources/<subject>/<slug>/`）

从上到下：

1. 面包屑与标题；学科、学段、教材锚点、页数；按钮「全屏打开」「下载单文件」。
2. 内嵌试玩：16:9 的 iframe 加载 `/interactives/<file>?embed=1`。
3. 课堂使用步骤：`quickstart` 逐条编号。
4. 教学设计：资源 md 正文，用全站 `.prose` 样式。
5. 相关课程：`relatedLessons` 对应的课。

### 5.4 Skill 工坊板块（`/skills/`）

- 页头一句话：「每个 Skill 都在 WorkBuddy 上用真实教师任务实测过，分数、短板和证据都公开。」右侧入口「评价标准」。
- 左栏品类列表，带已实测计数；右栏卡片，排序可选「评分」「最新评测」。
- 卡片：显示名、`does`、总分与档位、五维小条、平台徽章、`verdict`、证据标记、评测日期。
- 页面底部两块折叠区：「候选池」（待测，只有名称、来源、一句话，不出分）、「测过不收」（名称、原因、评测日期）。
- 没有任何已实测条目的品类不出现在左栏。

### 5.5 技能详情页（`/skills/<slug>/`）

左栏：

1. 它替你做什么：`summary`，加评测时的输出截图（最多 3 张）。
2. 怎么装：`install.workbuddy` 逐条编号；镜像的给「下载技能包」，只评不转的给「去来源页安装」；另给「复制安装话术」按钮，复制一句可发给 Agent 的安装指令：镜像的是「请从这个地址下载并安装技能：{站点}/skills/{slug}.zip」，只评不转的是「请安装技能 {name}：{上游地址}」。
3. 怎么用：`trigger`、`examples`、要先准备什么。
4. 要注意：`weakness` 与 `cautions`。
5. 评测档案：实测记录表（轮次、是否触发、耗时、修改处数、严重错误）、检查单逐条表（通过与否与说明）、与不装技能的对比、正文（输出样例与修改处清单）。
6. 可选「改成你自己学校的版本」：`customize`。

右栏（吸顶）：

1. 评分卡：总分、档位、五维条（每维分数与一句依据）、证据标记、评测环境（Agent、模型、日期、技能版本）；有平台评分时并列一行。
2. 来源：作者、上游链接、许可证、版本、构成、依赖。

### 5.6 评价标准页（`/skills/standard/`）

从上到下：三个问题；五维与权重；每一档怎么判（每维一张 1 到 5 的锚点表）；红线；档位；我们怎么测（archify 流程图加五条规矩）；品类检查单（按品类折叠）；证据标记与平台评分的分工；变更记录（标准版本与日期）。

### 5.7 工具箱板块（`/toolbox/`）

把页头换成资源中心页头（工具箱标签高亮），下面保留 h2「工具箱」与现有的原则说明。左栏堆叠滑卡、分类条、卡片网格及其脚本全部不动。

## 6. 脚本与构建

| 脚本 | 作用 |
|---|---|
| `scripts/audit_skill.mjs <dir>` | 只读静态审查：文件清单、SKILL.md 行数、frontmatter 字段、构成判定、风险模式命中（文件与行号）、外部域名、许可证识别；输出 JSON 与人读报告 |
| `scripts/build_skill_packages.mjs` | 把 `src/skills/<slug>/` 打成 `public/skills/<slug>.zip`，补 LICENSE 与 ATTRIBUTION.md |
| `scripts/check_skills.mjs` | 4.1 的全部约束、分数重算一致、证据截图存在、技能包新鲜、无 emoji |
| `scripts/gen_skill_task_data.mjs` | 固定种子生成 `public/skill-tasks/grade-sample.csv` |

`package.json`：`build` 最前面加 `build:skills`；新增 `check:skills`；`verify.mjs` 在「单文件构建」之后加一阶段「Skill 工坊校验」。

## 7. 入库流水线（含代测）

按 3.8 的流程逐个执行。代测的操作细则写在项目技能 `skills/skill-evaluation/SKILL.md`，`AGENTS.md` 加一条规则指向它。代测的边界：

- 只往 `~/.workbuddy/skills/` 放一个带 `hvtest-` 前缀的测试目录，用完删除；不读 `~/.workbuddy` 下的凭据、记忆、会话文件。放入后若 WorkBuddy 没有识别到新技能，重启一次 WorkBuddy。
- 界面自动化操作 WorkBuddy 桌面版：新建任务、粘贴任务原文、等完成、截图、导出回答。
- 每次实测记下当时 WorkBuddy 选用的模型；三次主任务用同一模型。
- 界面自动化连续三次失败时停下，向用户说明并请其在终端做一次性登录，改走无界面命令行。

## 10. 验收标准

1. `npm run build`、`npm run check:skills`、`npm run check:interactives` 全部退出码 0。
2. `scripts/check_skills.mjs` 对一条故意写错分数的条目报错（用临时副本验证后删除）。
3. 全站不存在指向 404 的站内链接；`/toolbox/` 与 `/resources/` 旧地址仍可访问。
4. 每个页面在 1440×900 与 375×812、深色与浅色下各截一张图，逐张目视：无溢出、无不可读文字、无空白块。
5. 课件详情页的 `quickstart` 逐步在浏览器里照做过。
6. 每个已实测技能的评测档案有输出截图，截图亲眼核对过与记录相符。
7. 首批评测完成后按 3.4 校准档位，结论写进变更记录。
8. 以上全过后把截图交给用户看，用户确认后再部署。

## 11. 不做的事

在线投稿表单、用户打分与评论、定时同步 SkillHub、恢复外链精选、内嵌 SKILL.md 原文、改动工具箱的交互与内容、改动旧物种课件模板。

## 12. 风险

| 风险 | 对策 |
|---|---|
| 界面自动化不稳定，代测中途失败 | 7 节的止损线；连续三次失败就停，改请用户做一次性登录 |
| 用户的 WorkBuddy 里装有其他技能与个人记忆，可能干扰触发 | 每次用新会话；档案里记下当时已启用的技能数量；触发率异常时在档案里注明 |
| 镜像技能随上游更新而过时 | 记录评测时的提交号；上游更新后复测，未复测的超过 6 个月标「待复测」 |
| 代测占用用户的 WorkBuddy 额度 | 控制在 37 次，单次任务输出限在一课时教案的篇幅 |
| 评分规则首批跑完发现拉不开差距 | 3.4 的校准步骤 |
| 品类检查单是初版，条目未必合教研员的意 | 评价标准页公开全部条目；检查单改版走变更记录，已评条目按新检查单复算 |
